# Live Deck v1 编写规范

这是一种独立的演示文稿格式：**一个 UTF-8 JSON 文件描述幻灯片、真实终端、图表面板、各自的命令候选池，以及跨面板的演示顺序。** 文件不依赖 Lark Bridge。当前播放器运行在 Jupyter 中，使用 reveal.js 展示普通页。

建议文件名：`主题.livedeck.json`。它仍是标准 JSON；`.json` 也能导入。不要输出 `.pptx`、Notebook 或完整 HTML 来代替它。

- [可直接交给另一位 AI 的生成提示词](AI-PROMPT.md)
- [JSON Schema](../live-deck.schema.json)
- [最小完整示例：普通页与两个独立终端](../examples/minimal.livedeck.json)
- [完整分屏示例：命令、Grafana、日志](../examples/multi-panel.livedeck.json)
- [运行参数、监控组与多图联动规范](MONITORING.md)及[完整联动示例](../examples/monitoring.livedeck.json)
- [打开当前播放器](../index.html)
- [打开分屏演示](../index.html?deck=multi-panel#/0)

仓库内部分示例带有 `{{LIVE_DECK_ROOT}}`、`{{LIVE_DECK_WORKSPACES}}`、`{{LIVE_DECK_URL}}` 安装占位符，仅由安装脚本处理；它们不是通用 v1 格式的变量语法。安装后的网页示例和导出文稿已替换为实际路径。

本文描述当前开源播放器实现。新增版本应同时更新播放器、校验器、Schema 和本文。新文件显式写 `"format":"live-deck","version":1`；旧文件省略这两项时按 v1 读取。

## 1. 最短交付流程

1. 将本文和 `AI-PROMPT.md` 交给生成文稿的 AI，补充主题、讲解目标、真实命令、工作目录、服务/数据前提和 Grafana 链接。
2. 让 AI 生成完整 `*.livedeck.json`。如需较长的 Python/Bash 程序，另交付脚本文件，候选命令只负责调用脚本。
3. 用下文的本地校验命令检查 JSON 与面板/命令引用。
4. 打开播放器，点 **编辑演示 → 导入 JSON → 保存并打开**。仅把文件写到磁盘不会自动替换播放器内容。
5. 在真实环境中排练命令，检查结果、进程生命周期和环境重置。格式校验不会执行命令，也不保证命令正确。

编辑保存在当前浏览器的演示副本中；“导出”生成配置文件。导出的 JSON 不包含正在运行的 Shell、终端输出、AI 对话或演示进度。

## 2. 核心对象

| 对象 | 用途 | 是否自动执行 |
| --- | --- | --- |
| `slides` | 文稿页序，可以混排普通页、单终端页、多面板页 | 翻页不执行命令 |
| `terminals` | 真实 Shell 的定义、初始工作目录和候选命令 | 首次展示时创建/连接终端 |
| `dashboards` | Grafana 等网页面板、初始 URL 和候选链接 | 首次展示时加载初始 URL |
| `commands` | 一个面板的候选池；终端存命令，图表存 URL | 点击候选只选中，不执行 |
| `sequence` | 将不同候选池的动作串成一条总演示顺序 | 标记完成只推进顺序 |

**页序、Shell 状态和演示顺序是三个独立概念。** 切到别的页不会关闭终端；临时选其他候选不会改变总顺序；标记步骤完成不代表程序已经运行成功或结束。

命令、页面、面板定义和总步骤不设固定数量上限。候选池分页只限制每次渲染的行数；实际容量受浏览器内存和本地存储影响。

## 3. 文件顶层

```json
{
  "$schema": "https://raw.githubusercontent.com/KuribohG/LiveDeck/main/web/live-deck.schema.json",
  "format": "live-deck",
  "version": 1,
  "id": "storage-demo-rehearsal-01",
  "title": "存储服务现场演示",
  "terminals": {},
  "dashboards": {},
  "slides": [
    {"type": "slide", "title": "演示目标", "markdown": "说明今天要验证的结论。"}
  ],
  "sequence": []
}
```

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| `$schema` | 可选字符串 | 给编辑器/AI 的 Schema 地址；播放器不依赖下载它 |
| `format` | 新文稿填写 `"live-deck"` | 旧文稿可省略，填写其他值会拒绝 |
| `version` | 新文稿填写数字 `1` | 当前不支持其他版本 |
| `id` | 必填字符串 | 1–80 位 ASCII 字母、数字、`_`、`-`；控制演示状态与终端身份 |
| `title` | 必填非空字符串 | 文稿标题 |
| `terminals` | 可选对象 | 键为终端 ID，值为终端配置；省略等同空对象 |
| `dashboards` | 可选对象 | 键为图表面板 ID，值为图表配置 |
| `slides` | 必填非空数组 | 页面按数组顺序展示 |
| `sequence` | 可选数组 | 跨面板提示顺序或监控组切换；空数组表示自由演示 |
| `monitorGroups` | 可选对象 | 命名监控组，详见 [监控联动](MONITORING.md) |

所有 JSON 字符串使用双引号，无注释，无尾逗号。不要用 `null` 代替可选对象或字符串；不需要的字段直接省略。未定义字段可能被忽略，不能据此发明播放器能力。

### ID 的三种作用域

- **文稿 ID**：顶层 `id`。同一文稿 ID + 同一终端 ID 会尝试恢复同一 Jupyter 终端。要开始一组全新 Shell，使用新的文稿 ID。
- **面板 ID**：`terminals` / `dashboards` 的对象键。整个文稿内唯一，两张表之间也不能重复。规则同文稿 ID，并禁止 `__proto__`、`constructor`、`prototype`。
- **命令 ID**：候选项的 `id`。在自己的池内唯一；可在不同面板中重复。格式接受非空字符串，建议仍用简短 ASCII 标识，例如 `start-server`。

标题、显示名称和 ID 分开：中文用于 `title` / `label`，稳定 ID 用于引用。

## 4. 普通幻灯片

```json
{
  "type": "slide",
  "kicker": "PART 01 / 背景",
  "title": "这次演示要回答什么？",
  "markdown": "我们将验证三件事：\n\n- 服务能够正常启动\n- 请求得到预期结果\n- 指标与日志能解释运行过程\n\n**先约定结果检查方式。**"
}
```

- 必填：`type:"slide"`、`title`。
- 可选：`markdown`（默认空）、`kicker`（页眉小字）。
- 支持 Markdown 段落、列表、表格、链接、代码块和图片。渲染结果经过 HTML 清理。
- Markdown 代码块只展示，不执行；要执行的命令放入终端候选池。
- 不要在正文里加 `<section>`、`<script>`、reveal.js 初始化代码或 Jupyter 单元代码。
- 图片优先使用观众浏览器可访问的完整 URL。相对图片路径相对播放器页面解析，不相对导入 JSON 所在目录解析。本格式不会自动上传附件。
- 内容过长就拆页。当前普通页使用固定演示画布，播放器不会自动把长段落分页。

## 5. 终端与候选命令

下面是 `terminals` 内的一项，不是独立完整文稿：

```json
{
  "runner": {
    "label": "01 · 主任务",
    "cwd": "/absolute/existing/demo-directory",
    "commands": [
      {"id": "where", "title": "确认运行位置", "command": "pwd", "note": "检查是否处于预期目录。"},
      {"id": "run", "title": "启动演示程序", "command": "python3 -u demo.py", "note": "启动后保持运行，下一步转到日志面板。"}
    ]
  }
}
```

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| `label` | 可选字符串 | 面板显示名称；省略显示 ID |
| `cwd` | 可选字符串 | 终端首次创建时的工作目录；建议已有的绝对路径 |
| `commands` | 必填数组，可为空 | 此终端自己的候选池 |
| 候选 `id` | 强烈建议填写 | 稳定引用；格式为池内唯一的非空字符串 |
| 候选 `title` | 必填字符串 | 演示者/观众能读懂的动作名称 |
| 候选 `command` | 必填字符串 | 将填入 Shell 的文本 |
| 候选 `note` | 可选字符串 | 展示目的、前提、预期结果、何时继续 |

`cwd` 不执行 `cd`，不创建目录，也不是变量模板。已有会话重新出现时，修改 `cwd` 不会改变当前目录；当前目录仍由该 Shell 中的 `cd` 决定。省略 `cwd` 使用 Jupyter 的默认终端目录。

### 编写能实际运行的命令

- “填入终端”不追加回车，也不清空已有输入。命令由演示者确认后按 Enter 执行。
- 候选命令要写成**单行**。可以调用预先准备的脚本；不要在 `command` 中放真正的换行、回车、ESC 或 Ctrl+C 等控制字符。
- JSON `"echo a\necho b"` 包含真实换行，不能直接填入；`"printf '%s\\n' hello"` 是合法单行命令。
- 长代码放在 `demo.py` / `demo.sh` 中，命令写 `python3 -u demo.py` / `bash demo.sh`。生成者应同时交付这些脚本或说明它们已存在。
- 后续命令依赖前面的 `cd` / `export` 时，必须引用同一个终端 ID。
- 持续运行的任务会占用该终端。并发操作放到另一个终端；需要返回 Shell 时，在 `note` 中提示演示者按 Ctrl+C。
- 不要使用 `echo` 伪造本应来自服务的响应。示例程序可以生成练习数据，但要标明其用途。
- 可复现性还需要固定依赖、输入、结果检查和环境重置。播放器本身不会替你准备这些。

### 单终端页

```json
{"type":"terminal","title":"启动任务","terminal":"runner"}
```

`terminal` 必须引用 `terminals` 中的 ID。它是单面板的快捷写法；新文稿也可以用 `workspace` 的单元素 `panels` 来表达。

## 6. 图表面板

下面是 `dashboards` 内的一项。`grafana.example.com` 只是说明性占位地址，正式文稿必须替换：

```json
{
  "metrics": {
    "label": "02 · 吞吐与延迟",
    "url": "https://grafana.example.com/d-solo/service/service?panelId=7&from=now-15m&to=now&refresh=10s",
    "commands": [
      {
        "id": "last-15m",
        "title": "查看最近 15 分钟",
        "command": "https://grafana.example.com/d-solo/service/service?panelId=7&from=now-15m&to=now&refresh=10s",
        "note": "观察任务运行时的变化，并检查时间范围和实例筛选。"
      }
    ]
  }
}
```

- `label` 可选，`commands` 数组必填，`url` 可选。`binding` 可绑定来源终端、URL 参数映射和运行时间，详见 [监控联动](MONITORING.md)。
- `url` 是首次打开面板时的地址；省略则等待演示者选择并打开一个候选链接。
- 图表候选的 `command` 是**完整 HTTP(S) URL**，不是 Shell 命令。点击“打开图表”才导航到选中 URL。
- 使用 Grafana 的 Share / Embed 功能取得真实链接，保留实例变量、时间范围、刷新周期和 panel ID。分屏通常更适合单 panel。
- 图表需要浏览器可访问，且目标服务允许 iframe。当前 Grafana 登录页已验证可嵌入，具体看板仍取决于用户登录和权限。首次使用可点“打开”。
- 不在 URL 或 JSON 中放账号密码、服务账号 token、Cookie。用户通过 Grafana 自身登录。
- 切换候选 URL 会重新加载这个图表 iframe；不会停止其他终端。
- Grafana 与主任务的对应关系由实际服务、指标、标签和时间范围决定；把它们放在同一页不会自动建立数据关联。

## 7. 多面板分屏页

```json
{
  "type": "workspace",
  "title": "运行任务，同时观察指标和日志",
  "panels": ["runner", "metrics", "logs"],
  "layout": "columns"
}
```

`panels` 是不重复、非空的面板 ID 数组，按布局顺序引用 `terminals` 或 `dashboards`。每个 ID 必须已定义。三个 ID 都来自 `terminals` 时，就是三个真实终端。

| `layout` | 显示方式 |
| --- | --- |
| `columns` | 默认，所有面板左右等宽排列 |
| `rows` | 所有面板上下等高排列 |
| `focus` | 第一个面板占左侧约 56%，其他面板在右侧上下排列；单面板时占满 |

演示时可以用操作栏“更多”菜单中的选择器临时切布局；临时选择不会写回文稿，重新进入页面仍按文件配置。多个面板过于拥挤时，拆成多个页面并复用 ID，或收起 AI / 候选详情。

同一个面板 ID 可以出现在多张页面里。播放器保留它的 iframe 和连接，只调整位置/可见性。一个页面里不能放两次同一个 ID。

## 8. 跨候选池的总演示顺序

```json
"sequence": [
  {"panel":"runner", "command":"prepare"},
  {"panel":"logs", "command":"follow"},
  {"panel":"runner", "command":"run"},
  {"panel":"metrics", "command":"last-15m"},
  {"panel":"runner", "command":"check-result"}
]
```

这里 `panel` 引用面板 ID，`command` 引用该池内候选项的 **命令 ID**。也接受从 0 开始的整数下标，例如 `{"panel":"runner","command":2}`，但生成新文稿时优先用 ID，防止插入命令后引用错位。

- 候选池不必按总顺序排列，可以有临时排障命令不加入 `sequence`。
- 同一个候选可在总顺序里出现多次；总进度按每一次步骤记录。
- 下一步会在顶部单行操作栏的“计划”按钮显示，同时高亮所属面板；候选区展开时也高亮对应命令。各面板的候选区默认折叠，由面板标题栏的“候选”按钮独立控制；选中命令、定位步骤和切组都不会自动展开。手动选择跨页保留，刷新后恢复折叠。点击“计划”可回到正确池和候选；旁边的命令输入框可编辑，点击“填入终端”后仍需回车执行。“完成本步”推进计划，上一步和跳过位于“更多”菜单。
- “标记本步完成”推进；“跳过”越过一步；“上一步”回退。均不执行命令、不终止进程。
- 选中其他候选只影响该池的选中项，不推进总顺序。
- 总顺序与页序独立。下一目标已在当前页时保留当前页；目标不在当前页时定位到文稿中第一张包含该面板的页面。
- **v1 没有“该步骤绑定第几页”的字段**。如果希望中间讲解普通幻灯片，由演示者翻页；不要生成虚构的 `slide`、`waitFor`、`dependsOn` 或 `autoRun` 字段。
- 每个出现在 `sequence` 的面板必须至少出现在一张页面中。

例如，主终端启动长任务后即可标记本步完成，下一步去图表观察。这个“完成”表示已完成演示动作，不表示长任务结束。

## 9. 状态、重排和重复排练

播放器上下工具栏默认收起；点击顶部边缘“顶部工具”展开编辑、导出和重置等入口，点击底部边缘“底部翻页”展开翻页入口。两条工具栏独立展开、收起，按钮始终位于对应工具栏与内容区的交界处。手动展开状态保持到本次页面关闭或刷新，不写入文稿和浏览器存储。终端获得焦点时可用展开后的底部按钮翻页。

点击播放器顶部“重置进度”可从头排练：总顺序和每个候选池回到开头，清空完成/跳过标记、命令草稿和搜索，返回第一页。同时关闭整份文稿的全部临时 tab，并重启全部固定 tab，包括其他页和刷新后尚未连接的会话；清空这些终端的输出和运行信息，固定 tab 从初始 cwd 启动。临时 tab 的名称和计划引用保留，可按需重新打开。重置期间禁用重复操作与终端输入，失败项会显示错误并允许重试。重置结果保存到当前浏览器，保留文稿、AI 对话和图表设置，不自动执行演示命令。这项操作无需新增文稿字段。

| 内容 | 保存位置与边界 |
| --- | --- |
| Shell、环境变量、当前目录、进程 | Jupyter 的真实终端进程；相同文稿 ID + 终端 ID 尝试恢复 |
| 终端之间的关系 | 不同 Shell 相互独立，但共享本机文件系统，不是隔离容器 |
| 候选选中项、草稿、完成标记、AI 对话、图表 URL、总顺序进度 | 当前浏览器本地存储，按文稿/面板区分 |
| 文稿配置 | 导入/编辑保存在当前浏览器，导出才成为可分发文件 |

刷新页面可重新连接已有终端；Jupyter 重启、终端被关闭或平台清理后，原进程状态无法恢复。新文稿 ID 只创建新的 Shell，不清理磁盘文件或撤销之前的操作。

修改 `sequence` 内容会重置总顺序进度。命令 ID 能保护总顺序的引用；但当前候选池的选中/完成标记仍按数组下标保存。大量重排候选或重新排练时，建议更换文稿 ID，避免沿用旧的池内标记。修改配置不会自动停止旧文稿的终端，可在 Jupyter Running 面板中管理旧会话。

## 10. AI 助手与文稿格式的边界

当前播放器通过 Codex 提供可选的 AI 建议，模型由服务器端配置。模型和凭证不写入文稿；生成 PPT 的 AI 无需添加 `ai` 配置。

分析摘要和正文流式显示，摘要可折叠；摘要说明观察依据与建议理由，不是内部原始推理。模型返回公开推理摘要时会标为“推理摘要”。中断时保留已收到内容并提示错误。终端、图表和 AI 面板都可全屏到浏览器内容区域；这些行为无需新增文稿字段。

每次提问读取当前选中步骤、附近候选、总顺序后续步骤、同屏终端近期输出和该面板最近对话。上下文按长度预算截取；文稿无固定条数上限不意味着模型能一次读取全部历史。

图表仅提供 URL，AI 目前不能自动读取跨站 Grafana 里的指标数值。需要 AI 分析指标时，演示者应在问题里提供观察结果，或在终端打印真实查询结果。

AI 建议在完整回答到达后显示，并标明目标面板；“采用”仅放入该面板编辑框，仍由演示者决定是否执行。

建议操作不固定条数，只需解释时可以没有操作。每条建议旁显示简短名称和用途说明，包括预期观察结果及必要的前置条件；说明不会拼入实际命令。生成文稿的 AI 无需为此修改 Live Deck 格式。

AI 标题栏的“新对话”清空当前面板的聊天记录，保留其他面板对话、演示进度、命令草稿与真实终端。下一次提问会继续使用终端历史和演示上下文，但不再带上已清空的聊天记录。回答生成期间需等待完成或报错后再开启新对话。

## 11. 校验与交付检查

下面的路径代表你的 Live Deck 源码目录：

```text
/path/to/LiveDeck
```

校验命令（只读文件，不执行其中命令，不创建终端）：

```bash
node /path/to/LiveDeck/scripts/validate-deck.mjs /absolute/path/to/my-demo.livedeck.json
```

可一次传多个文件。成功退出 0，输出页数、面板数、候选数和总步骤数；结构或引用有误退出 1。没有文件参数退出 2。

Schema 适合编辑器检查字段和类型；本地校验器还检查跨对象引用、重复面板、命令 ID 重复和总步骤是否有页面可承载。二者都不会检查 Shell 语法、脚本存在性、目录存在性、URL 可达性、Grafana 登录或命令执行结果。

生成者交付前应确认：

1. JSON 可解析，版本正确，所有引用完整。
2. 命令在实际机器运行，路径/参数来自用户资料，没有虚构服务或结果。
3. 长任务有对应观察面板，后续命令不会直接写入仍占用前台的程序。
4. 每步说明展示目的、观察点和继续条件。
5. 必需脚本、数据、初始化/重置说明一起交付。
6. 导入播放器排练，确认普通页、分屏、跨页会话、候选高亮和总顺序。

## 终端 tabs 与填入目标

每个终端面板都有 tab 栏。“＋”新增独立 Shell；双击 tab 名称可重命名。切换 tab、切页或全屏不会移除已有 iframe，也不会结束后台 tab 的进程。“重连”只恢复当前 tab 的连接，保留 Shell、变量和进程。“重启”先结束当前 tab 的旧 Shell，再按该 tab 配置的初始 cwd 创建新 Shell，清空终端输出和运行信息；固定 tab 与临时 tab 均可使用，名称和计划引用保留。重启期间不可填入或重复关闭该 tab；关闭失败时保留原会话并允许重试。其他 tab 不受影响，浏览器整页刷新仍重连已有会话。新 tab 默认继承面板的初始 cwd，不继承其他 Shell 的变量、SSH 会话或当前目录。

命令栏左侧选择填入目标。若当前候选对应计划本步，选择保存在该 sequence 步骤；否则保存在该候选命令。点击“填入终端”先显示目标 tab，等待连接就绪、调整显示尺寸，再输入命令并聚焦；不会追加回车。连接期间手动切换 tab 或离开终端页会取消本次填入。

新增 tab、名称与目标设置保存在当前浏览器的文稿副本，并包含在“导出”文件内。重置进度保留 tab 定义和目标设置，但关闭全部临时 tab、重启全部固定 tab。已有文稿无需修改，省略 tab 的命令进入 main（默认名 Tab 1），其终端名称与旧版本相同。

```json
{
  "terminals": {
    "host": {
      "label": "HOST",
      "tabs": {"main": {"label": "前台"}, "background": {"label": "后台"}},
      "commands": [{"id": "serve", "title": "启动服务", "command": "npm run dev", "tab": "background"}]
    }
  },
  "sequence": [{"panel": "host", "command": "serve", "tab": "background"}]
}
```

`terminals.<id>.tabs` 为可选对象；key 使用与终端 ID 相同的规则；每项可指定 label、cwd。main 始终存在。目标优先级为 sequence.tab → command.tab → main；同一命令可在不同计划步骤发到不同 tab。图表动作与监控组步骤不接受 tab。运行信息按 tab 隔离；图表 `binding.tab` 可指定数据来自哪个 tab，省略时跟随 main。AI 面板上下文包含各 tab 的标签、历史及运行信息。此扩展需要支持 tabs 的播放器；旧播放器不能保证将命令发到指定 tab。

### 固定 tab 与临时 tab

PPT JSON 中 `terminals.<id>.tabs` 声明的 tab 都是固定 tab，不提供关闭按钮；默认 main 也是固定 tab。点击“＋”新增的是临时 tab，名称旁显示“×”。临时身份保存在浏览器中，刷新后仍可关闭，不写入 PPT JSON 格式。

关闭临时 tab 时会提示确认，然后结束该 tab 的 Shell 连接并从 tab 栏收起；其他 tab 保持原会话。临时 tab 的名称和已有计划引用保留，可从“重新打开…”恢复；计划再次向它填入时，也会先建立新 Shell。关闭失败会保留 tab，便于重试；关闭期间不会继续填入或重新创建该终端。

“导出”包含当前所有 tab 的定义。将导出文件作为文稿导入或通过 JSON 编辑器保存后，其中声明的 tab 都变为固定 tab。固定与临时身份按浏览器保存的来源记录恢复；已保存为临时的 tab 刷新后仍可关闭。没有临时来源记录的 tab 按固定 tab 处理。

完整命名与引用示例见 [tabs.livedeck.json](../examples/tabs.livedeck.json)。
